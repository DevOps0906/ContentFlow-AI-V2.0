# 수익화·템플릿 실행 기획 — v2.1

**작성일:** 2026-11-05 · **상태:** 구현 전 제안 · **적용:** PRD v2.1

후속 구현: 사용자 요청으로 `apps/web` 로컬 대시보드와 글쓰기 템플릿 10종 선택을 추가했다. 아래 1절은 초기 분석 당시의 저장소 상태이며 서버·외부 연동·설치형 스킨은 여전히 미구현이다. 최신 구현 현황은 [작업 표](../../tasks/README.md)를 따른다.

## 1. 저장소 분석과 제품 방향

분석 범위는 README, PRD, 아키텍처, 논리 DB, 콘텐츠 템플릿, 에이전트 계약, 워크플로우, PDF 생성 스크립트와 CI다. 현재 저장소에는 서비스 앱, SQL migration, CMS 연동 코드, 실제 스킨 파일, 수익 데이터가 없다. 기존 문서의 기능은 구현 완료가 아닌 설계다. 원본 참고 PDF 16개와 XLSX는 저장소에 없어 분석하지 않았다. codebase-memory 프로젝트 목록/커버리지 조회에서 미인덱싱을 확인하여 파일을 직접 읽었다.

| 현재 설계의 장점 | 부족한 결정 | 보강 방향 |
|---|---|---|
| 출처·QA·사람 승인·멱등 발행 | 광고 운영의 시작 조건 | 사이트 준비 점검과 광고 상태를 콘텐츠 상태에서 분리 |
| 10종 글쓰기 구조 | 스킨/글/광고 템플릿 구분 | 세 계층의 버전·적용·복구 계약 정의 |
| 5개 채널과 SaaS 확장 | 첫 고객과 첫 출시 범위 | WordPress 중심 소규모 운영자부터 검증 |
| 실측/추정 수익 구분 | API 관측값도 예상 수익일 수 있음 | 데이터 출처와 정산 상태를 별도 축으로 관리 |
| 검색·수익 대시보드 | URL 매핑·기간·원가·결측 정의 | 비교 가능한 지표와 실행할 작업 큐 제공 |

**제품 약속 제안:** “근거 있는 글을 템플릿으로 제작하고, 어떤 글을 개선해야 운영 수익에 도움이 되는지 확인하는 블로그 운영 도구.” 글 생산량보다 편집 시간 절감과 개선 의사결정의 유용성을 먼저 검증한다.

첫 고객은 WordPress 블로그 1~3개를 운영하며, 직접 글을 검수하고 검색·광고 데이터를 확인할 수 있는 개인 운영자로 정한다. 초기 파일럿은 3~5명 제안이며 모집·수익 실적은 아직 없다. 대행사, 대량 무인 발행, 네이버 홈판 최적화는 후속 범위다.

## 2. MVP 경계와 플랫폼 역할

| 대상 | 최초 출시 | 후속 |
|---|---|---|
| WordPress | 공식 REST 초안 생성, 운영자가 게시 후 URL 확인, 기존 테마 유지 | 예약/업데이트 자동화, 테마 설정 적용 |
| 티스토리 | 정제한 본문 HTML·이미지·메타데이터 수동 패키지 | 독자 제작 스킨과 설치/복구 안내 |
| Blogger | 본문 export와 URL 기록 | OAuth/API 어댑터 검증 후 연동 |
| 네이버 | 후속 채널로 문서/글쓰기 프로필 유지 | 별도 애드포스트·제휴 지표; 애드센스 대상으로 취급하지 않음 |
| 자체 블로그 | 범위 밖 | CMS 어댑터와 운영 책임 별도 정의 |

MVP 글쓰기 템플릿은 T01 정보, T02 오류 해결, T04 비교 세 개다. 나머지 일곱 개는 카탈로그로 유지한다. 민감한 정책/금융 주제와 실사용 후기는 필요한 검수·증거 계약을 검증한 뒤 구현한다. 비주얼 빌더, React Flow 편집 UI, 결제/크레딧, 광고 자동 실험은 후속이다. 내부 데이터 모델에는 workspace 경계와 RLS를 처음부터 유지한다.

MVP 광고 설정은 **기록·점검·안내**까지다. 라이브 사이트의 광고 스크립트, 테마, CMP를 자동 변경하지 않는다. 기존 설정을 운영자가 플랫폼 관리 화면에서 적용하고 결과를 기록한다.

## 3. 운영 여정과 다음 행동

| 단계 | 입력/점검 | 화면의 다음 행동 | 완료 증거 |
|---|---|---|---|
| 연결 | 소유 블로그, CMS 권한, GSC/GA4 속성, 광고 데이터 유무 | 연결 또는 CSV 가져오기 | 연결 테스트/파일 검증 결과 |
| 준비 | 독창적 콘텐츠, 탐색, 공개 접근, 개인정보 안내, 사이트/광고 설정 | 누락 항목 보완 | URL·담당자·확인 시각 |
| 제작 | 검색 의도, 기존 글 중복, 원본 근거, 템플릿 | 초안 → 검수 → 승인 | 승인 버전과 차단 사유 0건 |
| 게시 | WP 초안 또는 수동 패키지 | 게시 후 URL 확인 | 원격 ID, 공개 URL, 확인 방식 |
| 측정 | 검색/방문/수익 보고서 | 데이터 연결 또는 수집 오류 해결 | 출처·기간·수집 시각 |
| 개선 | 노출 대비 검색 클릭, 글의 정보 신선도, 읽기 경험, 원가 | 제목/본문/내부링크 개선 제안 | 변경 전 버전·변경 이유·관측 기간 |

콘텐츠는 광고 승인 전에도 발행할 수 있다. 광고 준비 미완료가 일반 글의 발행을 막지 않도록 한다. 검색 색인 여부와 광고 승인 여부도 별개다.

## 4. 애드센스 준비·운영 계약

다음은 제품 내부 점검 체계다. Google의 승인 판정이나 법률 준수 인증을 대신하지 않는다. 독창적 콘텐츠와 사이트 HTML 접근 등 가입 요건은 [공식 자격 요건](https://support.google.com/adsense/answer/9724?hl=ko)을 따른다. 글 개수·글자 수·운영 일수를 합격 공식으로 제시하지 않는다.

| 점검 | 제품 동작 | 판정 경계 |
|---|---|---|
| 소유/접근 | 도메인·CMS 권한·공개 URL·크롤링 차단 확인 | 접근 가능이 색인/승인을 뜻하지 않음 |
| 콘텐츠/탐색 | 빈 페이지, 복제, 깨진 메뉴, 출처/권리 확인 | 점수만으로 정책 적합 판정 금지 |
| 운영자/개인정보 안내 | 안내 페이지 URL과 검토 기록 | 소개/문의는 운영 권장; 정책/지역별 의무와 구분 |
| 광고 연결 | 게시자 ID, 플랫폼 설치 위치, 중복 삽입 여부 기록 | ID 기록만으로 광고 게재 중이라 표시하지 않음 |
| ads.txt | 적용 가능 여부·게시자 ID·접근 결과·계정 상태 기록 | 권장 항목이며 미설치만으로 승인 불가 판정 금지 |
| 동의 관리 | 대상 방문 지역, CMP 필요 여부, 운영자 확인 | EEA/영국/스위스 개인 맞춤 광고의 인증 CMP 요건 별도 확인 |
| 게재 후 운영 | 정책 알림, 유입 급변, 잘못된 광고 배치 점검 | 자체 경보는 무효 트래픽 확정 진단이 아님 |

자기 광고 클릭, 클릭 유도, 인위적 노출/방문 생성은 지원하지 않는다. 광고를 버튼·다운로드·본문 링크처럼 보이게 배치하지 않는다. [애드센스 프로그램 정책](https://support.google.com/adsense/answer/48182?hl=ko)을 운영 기준으로 삼는다.

`ad_status`: `not_configured`, `preparing`, `review_pending`, `active`, `limited`, `rejected`, `disabled`, `unknown`. 내부 표준 상태이며 외부 원문 상태와 확인 출처/시각을 함께 보관한다. 자동 확인이 불가능하면 운영자 증빙으로 기록하고 자동 검증으로 표시하지 않는다. `active`에서 `limited`/`disabled`로 변경 가능하며, 오래된 기록은 재확인 대상으로 표시한다.

광고가 제한되어도 콘텐츠 수정·내보내기는 가능하다. 실제 광고 실행을 제어할 기능이 도입되면 사이트별 중지/복구와 적용 결과 확인이 선행되어야 한다. 현재 MVP는 안내와 운영자 확인만 제공한다.

ads.txt는 [공식 가이드](https://support.google.com/adsense/answer/12171612?hl=ko), CMP는 [지역별 동의 관리 요건](https://support.google.com/adsense/answer/13554116?hl=ko)을 참조한다. 정책 URL과 확인일을 보관하고 출시 직전 재확인한다.

## 5. 템플릿을 세 계층으로 분리

| 계층 | 역할/소유 데이터 | MVP 산출물 |
|---|---|---|
| 글쓰기 템플릿 | 답변·절차·비교·출처 등 의미 블록 | T01/T02/T04의 입력 계약·출력 예제·검수 규칙 |
| 사이트 표시 프로필 | 본문 폭, 글꼴, 제목/목차, 작성자/수정일, 관련 글 | 기존 WP 테마에 적용할 설정 가이드와 모바일 미리보기 |
| 광고 배치 프로필 | 플랫폼 지원, 후보 슬롯, 제외 영역, Auto ads 병용 여부 | 실제 스크립트 없는 배치 미리보기와 설치/복구 체크리스트 |

현재 레포의 ‘10종 템플릿’은 첫 계층이다. 설치 가능한 블로그 스킨은 아직 없다. 후속 스킨은 독자 제작하거나 사용권이 확인된 자산으로 구현하고 WordPress 테마, 티스토리 스킨, Blogger XML을 서로 다른 배포물로 취급한다.

초기 표시 프로필 제안: `L01 읽기 중심`(T01/T02), `L02 비교 중심`(T04). 모바일 표는 가로 스크롤 또는 카드로 제공하며 목차·앵커·키보드 탐색을 확인한다. 광고 프로필 제안: `A00 광고 없음` 기본, `A01 본문 구간 후보` 선택. A01은 순서가 있는 절차·코드·비교표·주요 버튼 내부를 제외하고 의미 블록 사이에만 후보를 표시한다. 슬롯 개수를 수익 공식으로 고정하지 않는다.

버전 묶음은 `content_template_version + layout_profile_version + ad_profile_version + renderer_version`으로 기록한다. 프로필이 바뀌면 미리보기/차이 확인/재승인 후 새 패키지를 만든다. 기존 발행물을 자동 변경하지 않으며 이전 묶음으로 되돌릴 수 있어야 한다. 본문 HTML에는 임의 script/event handler를 허용하지 않고, 허용 목록 기반으로 정제한다. 광고 코드는 글 본문 생성 모델의 출력에서 받지 않는다.

미리보기는 360/768/1440px에서 넘침·광고와 버튼 구분·이미지 영역 예약·목차 이동을 확인한다. 공개 페이지 성능 목표는 LCP 2.5초 이내, INP 200ms 미만, CLS 0.1 미만으로 제안한다. 현장 데이터가 없으면 미측정으로 표시하고 실험실 측정과 구분한다. 기준 참고: [Core Web Vitals](https://developers.google.com/search/docs/appearance/core-web-vitals).

## 6. 측정: 출처, 정산 상태, 귀속을 분리

‘API에서 받아온 값’과 ‘정산 확정 수익’은 다르다. API 관측 수익도 예상 수익일 수 있다. [AdSense API 지표](https://developers.google.com/adsense/management/reference/rest/v2/Metric)의 `ESTIMATED_EARNINGS`를 확정 매출로 표시하지 않는다.

필수 구분은 `provenance(api/csv/manual/model)`, `value_status(provider_estimated/finalized/modeled)`, `granularity(account/site/page)`, `coverage(complete/partial/unknown)`다. 관측 예상 수익과 가정에 의한 모델 예측은 합산하지 않는다. 확정 월 정산액은 월/계정 수준에서 별도 보존하며 일/글별로 임의 분해하지 않는다.

| 지표 | 정의/활용 | 결측·주의 |
|---|---|---|
| 검색 CTR | 동일 GSC 범위의 클릭 ÷ 노출 | 광고 CTR과 별도; 노출 0이면 N/A |
| 페이지 RPM | 동일 AdSense 보고서 수익 ÷ PAGE_VIEWS × 1,000 | GA4 조회수를 분모에 섞지 않음 |
| 기간 운영 기여액 | 같은 기간 관측 예상 수익 − 해당 기간 운영 비용 | 확정 이익 아님; 비용 범위/추정 여부 표시 |
| 글별 누적 기여액 | 귀속 가능한 누적 수익 − 제작비 − 누적 갱신비 − 배부 운영비 | 페이지 귀속 불가면 N/A 또는 명시적 모델 추정 |
| 손익분기 PV | 대상 비용 ÷ 가정 RPM × 1,000 | 기간·통화·비용 범위 명시; RPM ≤ 0이면 N/A |
| 회수 여부 | 동일 글 누적 귀속 수익이 누적 비용 이상인지 | 단순 월수 환산을 수익 예측으로 제시하지 않음 |

API는 `PAGE_URL` 차원을 제공한다. 따라서 글별 수익이 원천적으로 불가능하다고 가정하지 않는다. 실제 계정에서 차원/지표 조합과 제공 범위를 확인한 뒤 지원 여부를 결정한다. URL 정규화·쿼리·canonical 차이로 연결되지 않는 수익은 미귀속으로 남긴다. 사이트 총액과 페이지별 합계를 중복 합산하지 않는다. [차원 정의](https://developers.google.com/adsense/management/reference/rest/v2/Dimension).

GSC는 검색 노출/클릭, GA4는 방문/행동, AdSense는 광고 보고서의 원천이다. GSC 검색 데이터 수집 성공을 전체 URL 색인 확인으로 취급하지 않는다. 색인은 별도 검사 또는 운영자 확인이며, 검사한 URL 중 비율과 전체 사이트 추정을 구분한다.

MVP는 공식 내보내기 CSV로 검색/광고 데이터를 입력하고 GA4는 선택으로 둔다. CSV 형식은 출처별 샘플을 확보한 뒤 확정하며 미지원 형식을 자동 추정해 수입하지 않는다. API OAuth 동기화는 후속이다. 통화·보고 시간대·대상 사이트·기간·원본 파일 해시·가져오기 시각을 필수로 저장한다. 누락/미연결/지연은 0원과 구분한다. 같은 범위 재수입은 교체/버전 처리하여 중복 합계를 방지한다.

예시 가정: 월 20,000 PV, 가정 RPM 5,000원이면 예상 수익은 100,000원이다. 모델비 20,000원·호스팅 배부 10,000원·편집 노동비 60,000원을 같은 달 비용으로 잡으면 기여액은 10,000원이다. 단가는 검증되지 않은 예시이고 시장 평균/달성 약속이 아니다. 편집 노동을 제외하면 결과가 왜 달라지는지 함께 표시한다.

## 7. 콘텐츠 포트폴리오와 개선 큐

한 블로그에서 전문성이 있는 주제 하나를 정하고, 질문군과 기존 URL을 먼저 연결한다. 같은 검색 의도에 기존 글이 있으면 신규 글보다 갱신을 우선 검토한다. 초기 12개 콘텐츠의 제안 구성은 T01 4개/T02 4개/T04 4개다. 개수는 파일럿 작업량이며 애드센스 승인 요건이 아니다.

키워드 선택에는 독자 문제의 명확성, 직접 확보할 근거, 기존 글과 차이, 갱신 비용, 정책 위험을 사용한다. 검색량/CPC는 출처와 확인일이 있을 때만 참고한다. 고CPC만으로 민감 주제에 진입하지 않는다. AI 작성 시 직접 실험·스크린샷·비교 데이터 중 확보 가능한 증거를 지정한다.

| 관측 | 추천 행동 | 금지할 해석 |
|---|---|---|
| 노출은 있으나 검색 CTR 낮음 | 의도·제목·요약·SERP 맥락 검토 | 제목 수정이 클릭 상승을 보장 |
| 클릭은 있으나 읽기 경험 저하 | 도입·표·모바일·광고 배치 확인 | 광고 수부터 늘리기 |
| 유입 안정, 수익 변동 | 국가/기기/계절/게재 상태/표본 확인 | 모든 변화를 템플릿 효과로 단정 |
| 오래된 가격/정책 | 근거 재확인 후 버전 갱신 | 과거 글의 날짜만 갱신 |

개선 작업은 근거 지표, 대상 URL/버전, 예상 작업시간, 담당자, 검토 기한을 가진다. 자동 발행하지 않고 승인 큐로 전달한다.

## 8. 검증 계획과 출시 게이트

| 단계 | 검증 작업 | 통과 기준 |
|---|---|---|
| M0 기반 | 로그인, workspace, 연결정보, DB/RLS | 교차 테넌트 읽기/쓰기·비밀정보 노출 차단 |
| M1 제작 | 3종 템플릿, 각 1개 원고, 출처/승인 | 필수 블록 누락 차단, 수정 시 승인 무효 |
| M2 전달 | WP 초안과 티스토리 export | 중복 요청 1개 초안, HTML 정제, 수동 URL 확인 |
| M3 측정 | 사이트/가능하면 페이지 CSV, 비용 입력 | 재수입 중복 없음, 예상/확정/모델 분리, 결측 N/A |
| M4 파일럿 | 3~5명, 4주 제작 운영 후 8~12주 관측 제안 | 아래 가설을 평가하고 범위 재결정 |
| M5 확장 | API 수집, 나머지 템플릿, Blogger, SaaS | 반복 사용·비용·지원 부담 확인 후 결정 |

내부 목표 가설: 운영자 5명 중 3명 이상이 7일 내 검수 완료 글을 공개하고, 기존 수작업 대비 중앙 편집 시간이 30% 이상 감소하며, 3명 이상이 주간 개선 큐를 2회 이상 사용한다. 실제 모집 수에 맞춰 분모를 명시한다. 동일 운영자·비슷한 난도의 작업을 비교하고 주제 차이와 표본 부족을 함께 보고한다. 이 목표는 실적이나 업계 기준이 아니다.

광고/검색 데이터가 충분하지 않으면 수익 효과는 ‘검증 불가’로 남긴다. 초기 4주 안에 광고 수익 증가를 출시 필수조건으로 삼지 않는다. 템플릿 효과 실험은 한 번에 한 요소, 사전 기간/표본/중단 기준을 정의한 뒤 후속 구현한다. 트래픽이 적으면 통계적 우열을 선언하지 않는다.

## 9. SaaS 과금 가설과 미결정 사항

블로그 광고 수익과 ContentFlow 서비스 매출은 별개 장부다. 파일럿은 소유 블로그 연결 수와 작업량을 계량하고, 가격은 인터뷰·실제 사용 비용을 확인한 뒤 결정한다. 과금 후보는 워크스페이스 기본료 + 포함 생성량 + 초과 사용 상한이다. 무제한 생성을 약속하지 않는다.

서비스 공헌이익은 구독 매출에서 모델·인프라·결제·지원 변동비를 뺀 값으로 관리한다. 무료 체험에도 일/월 모델 예산을 둔다. 생성 실패/재시도 과금과 초과 한도는 결제 도입 전에 명시한다.

출시 전 결정할 사항: 파일럿 도메인/운영자 확보, 제공 가능한 CSV 샘플, WP 인증 방식과 권한, 티스토리 실제 HTML 호환성, 데이터 보존/삭제 기간. 결정 전에는 연결 성공·스킨 지원·예상 수익을 구현 사실처럼 소개하지 않는다.
