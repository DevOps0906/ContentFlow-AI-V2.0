# 다수 블로그 등록과 초과 슬롯 과금 (기능 명세, 가설)

상태: 초안 · 작업: CF-22(명세·계량·고지), CF-23(실결제, 범위 밖) · 상위: [MONETIZATION_STRATEGY.md#9](MONETIZATION_STRATEGY.md), [PRD.md#4](PRD.md), [PRD.md#7](PRD.md)

## 1. 목적·범위
- 목적: 한 워크스페이스에서 여러 블로그를 운영하게 하고, 포함 수를 넘는 활성 블로그에 추가 요금이 생길 수 있음을 미리 알리고 계량한다.
- 포함(CF-22): 플랜별 한도 검사, 활성 블로그 수 계량, 초과 고지·확인 기록, 다운그레이드 처리, 사용량 스냅샷.
- 비범위: 실제 청구·결제·영수증·세금·환불(CF-23, 위험 높음), 확정 가격, 블로그 광고수익 정산, 로컬 모드·데스크톱 로컬(과금 대상 아님).

## 2. 용어
| 용어 | 뜻 |
|---|---|
| 워크스페이스 | 과금·권한 단위. 소유자가 결제 주체. 사용자가 여러 개 가지면 각각 계산 |
| 활성 블로그 | `blogs.status = 'active'`. `archived`는 계산 제외 |
| 포함 수 | 플랜에 기본 포함된 활성 블로그 수 |
| 초과 슬롯 | 청구 기간 중 최대 동시 활성 수 − 포함 수 (0 미만이면 0) |
| 최대 상한 | 플랜과 무관하게 워크스페이스가 가질 수 있는 활성 블로그 수의 하드 한도 |
| 서비스 매출 | ContentFlow 구독·슬롯 매출. 블로그 광고수익 장부와 분리([MONETIZATION_STRATEGY.md#6](MONETIZATION_STRATEGY.md)) |

## 3. 플랜 가설표
모든 숫자는 가설이며 파일럿 후 확정한다. 금액은 미정(필요 시 `bm-calc`로 계산, 이 문서에 확정 금액 기재 금지). 무제한은 약속하지 않는다.

| 플랜 | 포함 블로그 수 | 초과 슬롯 허용 | 최대 상한 | 초과 슬롯 단가 |
|---|---|---|---|---|
| Free | 1 (가설) | 불가(상한 = 포함 수) | 1 | 해당 없음 |
| Basic | 3 (가설) | 가능 | 10 (가설) | 미정 |
| Pro | 10 (가설) | 가능 | 30 (가설) | 미정 |

- 기존 `workspaces.plan`(기본 `'free'`, 0001)을 플랜 값으로 쓴다. 지금 계정 모드 워크스페이스는 모두 Free로 시작하므로, CF-22 적용 전 이미 2개 이상 활성인 워크스페이스는 §5 "다운그레이드 보관 요구"가 아니라 **유예**(파일럿 기간 동안 한도 검사만 표시, 차단 없음)로 둔다.

## 4. 계산 규칙
- 계량 대상: 계정 모드 워크스페이스의 `active` 블로그만. 청구 기간은 워크스페이스 구독 주기(미결정 §10 일할계산 여부와 연동).
- 기준값: 기간 내 "최대 동시 활성 수"(peak). 보관 후 재등록으로 수를 낮춰 보이는 회피를 막는다.
- 초과 슬롯 = max(0, peak − 포함 수). 예상 추가 요금 = 초과 슬롯 × 단가(미정이므로 화면에는 "금액 미정").

예시(포함 수 N, 숫자는 설명용 가정):
| # | 상황 | peak | 초과 슬롯 |
|---|---|---|---|
| 1 | N=3, 기간 내 활성 2개 유지 | 2 | 0 |
| 2 | N=3, 5개 활성 후 기간 중 2개 보관해 3개로 마감 | 5 | 2 (마감 수가 아니라 peak) |
| 3 | N=3, A 보관 후 B 등록(항상 3개 이하) | 3 | 0 (교체는 동시 수를 늘리지 않음) |

## 5. 화면 흐름 (설정 > 블로그 계정)
기존 화면: `apps/web/src/components/blog-accounts.tsx`. 아래는 유형·구성 블록·상태·다음 화면 표(ux-patterns 2절). 

| 화면/요소 | 유형 | 구성 블록 | 상태 | 다음 |
|---|---|---|---|---|
| 블로그 계정 목록 | 설정 목록 | 사용량 배지("활성 n / 포함 m"), 추가 버튼, 행(이름·상태·보관) | 빈·로딩·저장 실패·한도 도달·보관 필요 | 추가 대화상자, 보관 확인 |
| 초과 고지 | alert dialog([OVERLAY_UX.md](../07-design/OVERLAY_UX.md)) | 제목 "월 추가 요금이 발생할 수 있습니다", 현재/추가 후 수, 금액 "결제 준비 중·미정", 체크 확인, 취소·추가 | 체크 전 추가 비활성, 실패 시 오류 문구 | 목록 복귀 |
| 한도 상한 안내 | 인라인 안내 | 상한 도달 문구, 보관 또는 플랜 변경 안내 | 추가 버튼 비활성 | 플랜 화면 |
| 다운그레이드 보관 요구 | 배너+선택 목록 | 초과 수, 보관할 블로그 선택 | 선택 전 새 글·키워드 연결 차단 | 보관 확인 후 해제 |

- 3구간: 모바일(~767)은 목록 카드형·대화상자 전체 폭 하단, 태블릿(768~1199)·데스크톱(1200~)은 표형·중앙 대화상자. 폰트 크기는 디자인 토큰.
- 키보드: 대화상자 포커스 트랩, Esc 취소, 확인 체크박스 Tab 도달.
- 권한: 소유자·관리자만 추가·보관 가능, 소유자만 결제·플랜 변경. 편집자는 읽기(사용량 배지만).

## 6. 상태·오류
| 코드 | 조건 | 사용자 문구 방향 |
|---|---|---|
| `BLOG_LIMIT_CONFIRM_REQUIRED` | 포함 수 초과 + 확인 미동반 | 추가 요금 고지 후 확인 요청 |
| `BLOG_LIMIT_REACHED` | 최대 상한 도달 | 보관 또는 플랜 변경 안내 |
| `PLAN_NOT_ALLOWED` | Free 등 초과 불가 플랜 | 플랜 변경 안내 |
| `BLOG_OVER_ENTITLEMENT` | 다운그레이드 후 초과, 새 글·키워드 연결 시 | 보관 선택 요구 |
| `FORBIDDEN_ROLE` | 소유자·관리자 외 | 권한 안내 |
- 결제 미연동 단계는 "청구됨·결제됨" 표시 금지. 문구는 "결제 준비 중".

## 7. 데이터 (초안, 마이그레이션 아님)
| 테이블 | 핵심 컬럼 | 비고 |
|---|---|---|
| `workspace_entitlements` | `workspace_id`(PK), `plan`, `included_blogs`, `max_blogs`, `overage_allowed`, `updated_at` | `workspaces.plan`(0001)과 일치 유지. RLS: 멤버 읽기, 쓰기는 서버만 |
| `blog_usage_snapshots` | `workspace_id`, `period_start`, `period_end`, `peak_active`, `active_at_close`, `overage_slots`, `created_at` | 기간 중 peak 갱신. 금액 컬럼 없음(CF-23) |
| `audit_logs`(기존) | `action` = `blog.overage_ack` | `payload`: 현재 수·추가 후 수·포함 수·고지 문구 버전 |
- 강제: `blogs` insert 및 `archived → active` 전환 시 DB 트리거가 한도 검사(최대 상한 초과 거부, 포함 수 초과는 확인 기록 필요). 동시 요청은 워크스페이스 행 잠금으로 직렬화.
- 상태 규칙은 DB가 최종 강제([AGENTS 지침](../../AGENTS.md))이므로 앱 검사는 보조.

## 8. API (초안)
| 메서드·경로 | 입력 | 출력 | 권한 | 오류 |
|---|---|---|---|---|
| `GET /api/blogs/usage` (신규) | - | 활성 수, 포함 수, 상한, peak, 초과 슬롯 | 멤버 | 403 |
| `POST /api/blogs` (기존, 현재 워크스페이스) | 블로그 정보 + `acknowledgeOverage` | 생성된 블로그 | 소유자·관리자 | §6 코드 |
| `PATCH /api/blogs` (기존, 보관·복원) | `id`, `status` + `acknowledgeOverage` | 갱신 | 소유자·관리자 | §6 코드 |
- 브라우저는 Supabase와 직접 통신하지 않는다. service role 키를 앱에 넣지 않는다. 권한은 기존 블로그 계정 규칙(소유자·관리자)과 같다.

## 9. 부정 시나리오
| 시나리오 | 대응 |
|---|---|
| 보관 후 재등록으로 peak 회피 | peak 기준 계량, 재활성화도 한도 검사 |
| 보관 직후 스낵바 "되돌리기"(복원)로 초과 | 복원도 `archived → active`라 같은 한도 검사. 초과면 스낵바 대신 고지 대화상자 |
| 확인 없이 API 직접 호출 | 트리거·API가 확인 기록 없으면 거부 |
| 동시 추가 경쟁 | 워크스페이스 행 잠금, 상한 재검사 |
| 다운그레이드로 데이터 삭제 기대 | 삭제 안 함. 보관 선택 요구, 기존 글 유지 |
| 편집자가 블로그 추가 | `FORBIDDEN_ROLE`(RLS+트리거) |
| 다중 워크스페이스로 한도 분산 | 워크스페이스별 계산이 원칙. 남용 판단은 미결정 |
| 로컬 모드 데이터로 과금 | 로컬은 계량 안 함, 계정 모드 전환 시 시점부터 계산 |

## 10. 인수 조건
- [ ] 포함 수 이하 추가는 고지 없이 성공, 초과 추가는 대화상자 확인 후에만 성공하고 audit 기록이 남는다.
- [ ] 최대 상한에서 추가·재활성화가 DB 수준에서 거부된다(API 우회 포함).
- [ ] archived는 계산 제외, peak 예시 3개가 단위 테스트로 일치한다.
- [ ] 다운그레이드 시 블로그 삭제 없음, 보관 선택 전 새 글·키워드 연결 차단, 기존 글은 열람·수정 가능.
- [ ] 화면 어디에도 청구·결제 완료 표시와 확정 금액이 없다. 로컬 모드에는 고지가 없다.
- [ ] 3구간 레이아웃, 키보드, 저장 실패, 빈 상태를 처리한다.
- 보안: 위험 높음 영역(트리거·권한)이므로 구현 후 `reviewer(security)` 필요. 결제사 연동(CF-23)은 `challenger`·보안 리뷰 후 사용자 승인으로만 착수.

## 11. 미결정 사항
| 항목 | 상태 |
|---|---|
| 플랜별 포함 수·상한·슬롯 단가 | 미확인, 인터뷰·파일럿 근거 필요 |
| 결제사·결제 수단 | 미정(CF-23) |
| 세금(부가세 등)·환불·영수증 | 미정, 법무 확인 필요 |
| 일할계산 여부, 청구 기간 경계 | 사용자 결정 필요. 권장: 일할 없음, 월 단위 peak(가장 단순·설명 쉬움) |
| 다중 워크스페이스 남용 기준 | 사용자 결정 필요. 권장: 소유자당 Free 워크스페이스 1개 |
| 고지 문구 버전 관리 | 구현 시 결정 |
