# 네이버 홈판 모듈 (기획 초안 r1)

버전: **r1** (2026-11-16) · 상태: **기획 초안, 구현 전** · 작업: CF-25(제안) · 상위: [PRD.md](PRD.md)(§6 네이버 홈판, §9 비목표), [MONETIZATION_STRATEGY.md](MONETIZATION_STRATEGY.md) · 글쓰기 기준: [NAVER_HOMEFEED_RULES.md](../04-content/NAVER_HOMEFEED_RULES.md)

현재 상태: 네이버는 **수동 발행 후속 채널**이다([PRD.md#4](PRD.md) P0-08). 이 문서는 근거 문서이며, 구현 전에는 화면·문구가 홈판 노출·수익을 말하지 않는다. 지금 동작하는 것은 네이버 검색형/홈판형 제목 프로필 문구([CONTENT_TEMPLATES.md#2](../04-content/CONTENT_TEMPLATES.md))와 T06 템플릿 계약, Title Lab(`titles.ts`, 규칙 기반)이다.

근거 등급: **[공식]** 네이버 발표 · **[자료]** 강의·뉴스레터 등 2차 주장(미검증) · **[노트]** 특강 노트 제목만 확인 · **[규칙]** 사용자 결정 · **[제안]** 이 문서의 판단.

## 1. 목적·범위
- 목적: 운영자가 네이버 블로그 글을 **글 목적(발견/문제해결/전환)별로 기획**하고, 제목·썸네일·본문 품질을 점검하고, 발행 후 **지면별 성과를 기록**해 다음 글을 개선한다.
- 비범위(결정 전까지 유지):

| 비범위 | 이유 |
|---|---|
| 홈판 노출 보장·예측 점수 | 알고리즘 비공개. 공식 안내는 이웃 관계·관심사·활동 이력 [공식] |
| 네이버 자동 발행·자동 댓글·자동 이웃 추가·조회수 조작 | 정책 위험, 기존 "자동 발행은 후속" 원칙 |
| 네이버 통계 API 자동 수집 | 공식 수집 경로 미확인([ANALYTICS_SYNC.md#1](ANALYTICS_SYNC.md)와 동일). 수동/CSV 유지 |
| 클립 영상 편집·업로드 자동화 | 공식 업로드 API 미확인. 연계 계획 기록만 |
| 홈판용 노하우의 사실 단정 | 대부분 강의 판매자 주장 [자료]. 화면에 근거 등급을 표시 |

## 2. 사실·주장 정리
| 구분 | 내용 | 등급 |
|---|---|---|
| 추천 기준 | 이웃 관계, 관심사, 활동 이력 기반 추천 | [공식] 네이버 보도자료(2025-09) |
| 클립 | 블로그 정보 스티커로 글 연결, 클립 크리에이터 광고 인센티브·쇼핑·브랜드 커넥트 | [공식] 기능 존재, 수치·자격은 회차별 확인 필요 |
| 썸네일이 가장 중요 | 피드에서 가장 먼저 보이는 요소, 결과물 화면+짧은 문구, 모바일 크기 가독성 | [노트]·[자료] 근거 약함, A/B 기록으로 검증 |
| 글 유형 비율 | 발견 5 : 문제해결 3 : 전환 2 | [제안] 성과 기록으로 조정 |
| "공식 체크리스트 3가지" | 슬라이드 문구만 확인, 출처 미확인 | 미확인 — 제품에 공식으로 쓰지 않음 |
| 쇼핑커넥트 수수료 | 자료마다 5~20%·최대 18%·최대 50% 상이 | 미확인 — 상품별 직접 확인 |
| 리트리버 로직·Creator Advisor 지표·클립 수익화 수치 | 특강 노트(스크린샷) 미판독 | 미확인(§8) |

## 3. 기존 기능과의 연결 (코드 변경 후보, 이번 작업에서는 변경하지 않음)
| 모듈 | 내용 | 연결 지점 | MVP |
|---|---|---|---|
| H1 글 목적 분류 | 글마다 발견/문제해결/전환 지정, 목적별 제목 공식·본문 중심 안내 | 브리프의 "발행 채널"([PRD.md#4](PRD.md) P0-02), T01/T05/T06 | ✅ |
| H2 제목 | **메인 키워드 1 + 세부 키워드 1개 이상 필수**([규칙]), F1/F2 공식, 9항목 점검 | `titles.ts`(패턴·경고), Title Lab 평가(P0-03) | ✅ |
| H3 키워드 세트 | 메인 1 + 세부 3+ + 서브 | `keywords.ts`, 키워드 화면 | ✅ |
| H4 썸네일 | 문구 후보, 8항목 점검표(수동 체크) | 편집기 검수 패널(`qa.ts`/`review.ts`) | ✅ |
| H5 본문 품질 | 직접 경험·실제 화면·도입부 점검(규칙 기반 경고, 차단 아님) | QA Center(P0-06) 경고 패턴 | ✅ |
| H6 성과 기록 | 지면별 조회(홈판/검색/기타)·댓글·이웃 증가·썸네일 유형 수동 입력 | `blog-metrics.ts`, 개선 큐(P0-14) | ✅ |
| H7 클립 연계 | 글당 클립 1편 계획, 스티커 연결 여부 기록 | 개선 큐 | 후속 |
| H8 수익 연결 | 전환글의 쇼핑커넥트·애드포스트 지표를 수동 기록(광고 대상 아님) | `revenue.ts` N/A 규칙 | 후속 |
| H9 프롬프트 보관함 | 제목·썸네일·본문 프롬프트 버전 관리 | AI Writer 프롬프트 버전(P0-05) | 후속 |

원칙: 새 점검은 **경고**이며 발행을 막지 않는다(차단은 기존 P0-06 규칙만). 제목 규칙 위반도 경고로 표시한다. 실제 데이터가 없으면 N/A로 표시한다([AGENTS.md](../../AGENTS.md)).

## 4. 사용자 흐름
1. 키워드 세트 작성(메인·세부·서브) → 2. 글 목적 선택 → 3. Title Lab에서 규칙 통과 제목 선택 → 4. 썸네일 문구·점검 → 5. 본문 작성·검수(직접 경험·화면) → 6. 승인 → 7. **수동 발행** → 8. 공개 URL 확인 → 9. 2주 뒤 지면별 성과 기록 → 10. 개선 큐로 제목·썸네일 유형 비교.

## 5. 데이터 후보 (스키마 변경은 구현 단계에서 별도 마이그레이션·RLS 시험 필요)
| 항목 | 필드(후보) |
|---|---|
| 글 | `post_purpose`(discovery/solution/conversion), `title_formula`(F1/F2) |
| 키워드 세트 | main 1, details 3+, subs |
| 제목 | 본문 제목, 사용한 메인/세부 키워드, 점검 결과 |
| 썸네일 | 유형(사진/스크린샷), 문구, 점검 결과 |
| 성과 기록 | 기록일, 유입 지면별 조회, 댓글, 이웃 증가, 클립 연계 |

기존 [DATABASE_SCHEMA.md](../03-database/DATABASE_SCHEMA.md) 8절과 충돌하는지 구현 전 확인한다. 상태 전이표는 바꾸지 않는다(`lifecycle.ts`와 SQL 전이표 동시 변경 규칙).

## 6. 화면·반응형
기존 화면 확장으로 시작한다: 키워드 화면(세트·세부 키워드), 편집기(글 목적·제목 점검·썸네일 점검), 분석 화면(지면별 성과). 3구간 반응형·키보드 접근·빈 상태·저장 실패를 처리한다.

| 구간 | 본문 | 보조 | H1 | H2 | 버튼 |
|---|---|---|---|---|---|
| 모바일(~767) | 15px | 13px | 22px | 18px | 15px |
| 태블릿(768~1199) | 16px | 14px | 26px | 20px | 16px |
| 데스크탑(1200~) | 16px | 14px | 30px | 22px | 16px |

기존 `DESIGN.md` 토큰과 다르면 `DESIGN.md`를 우선하고 이 표를 맞춘다.

## 7. 린 검증과 단계
| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 0 (앱 없이) | 규칙 문서와 스프레드시트로 4주간 글 12~16편 운영, 성과 수동 기록 | 지면별 조회·썸네일 유형별 반응 비교 가능 |
| 1 | H1·H2·H3 (목적·제목 규칙·키워드 세트) | 제목 점검 단위 테스트, 규칙 위반 경고 |
| 2 | H4·H5·H6 (썸네일·본문 점검·성과 기록) | 점검 경고 테스트, 성과 N/A 규칙 |
| 3 | H7~H9 | 단계 0~2 성과 확인 후 결정 |

단계 1 착수 조건: 단계 0 기록에서 제목·썸네일 유형별 차이를 한 번 이상 확인.

## 9. 수익화·리스크
- 홈판은 **트래픽(구경형 독자)**, 검색·전환글이 **수익**이라는 구분은 [자료] 주장이다. 수익은 전환글에서만 연결한다.
- 위험: 근거 약한 노하우를 사실처럼 표시, 광고성 글 비율 증가로 신뢰 저하, 정책 변경. 대응: 근거 등급 표시, 비율 기록, 규칙 문서 버전 관리.
