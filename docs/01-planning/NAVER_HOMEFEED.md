# 네이버 홈판 모듈 (기획 초안 r1)

버전: **r1** (2026-11-16) · 상태: **기획 초안, 구현 전** · 작업: CF-25(제안) · 상위: [PRD.md](PRD.md)(§6 네이버 홈판, §9 비목표), [MONETIZATION_STRATEGY.md](MONETIZATION_STRATEGY.md) · 글쓰기 기준: [NAVER_HOMEFEED_RULES.md](../04-content/NAVER_HOMEFEED_RULES.md)

현재 상태: 네이버는 **수동 발행 후속 채널**이다([PRD.md#4](PRD.md) P0-08). 이 문서는 근거 문서이며, 구현 전에는 화면·문구가 홈판 노출·수익을 말하지 않는다. 지금 동작하는 것은 네이버 검색형/홈판형 제목 프로필 문구([CONTENT_TEMPLATES.md#2](../04-content/CONTENT_TEMPLATES.md))와 T06 템플릿 계약, Title Lab(`titles.ts`, 규칙 기반)이다.

근거 등급: **[공식]** 네이버 발표 · **[자료]** 강의·뉴스레터 등 2차 주장(미검증) · **[노트]** 특강 노트 제목만 확인 · **[규칙]** 사용자 결정 · **[제안]** 이 문서의 판단.

## 1. 목적·범위
- 목적: 운영자가 네이버 블로그 글을 **글 목적(발견/문제해결/전환)별로 기획**하고, 제목·썸네일·본문 품질을 점검하고, 발행 후 **지면별 성과를 기록**해 다음 글을 개선한다.
- 비범위(결정 전까지 유지):

| 비범위 | 이유 |
|---|---|
| 홈판 노출 보장·예측 점수 | 알고리즘 비공개. 공식 안내는 이웃 관계·관심사·활동 이력 [공식] |
| 네이버 자동 발행·자동 댓글·자동 이웃 추가·조회수 조작 | 정책 위험, 기존 "자동 발행은 후속" 원칙 |
| 네이버 통계 API 자동 수집 | 공식 수집 경로 미확인([ANALYTICS_SYNC.md#1](ANALYTICS_SYNC.md)와 동일). 수동/CSV 유지 |
| 클립 영상 편집·업로드 자동화 | 공식 업로드 API 미확인. 연계 계획 기록만 |
| 홈판용 노하우의 사실 단정 | 대부분 강의 판매자 주장 [자료]. 화면에 근거 등급을 표시 |

## 3. 기존 기능과의 연결 (코드 변경 후보, 이번 작업에서는 변경하지 않음)
| 모듈 | 내용 | 연결 지점 | MVP |
|---|---|---|---|
| H1 글 목적 분류 | 글마다 발견/문제해결/전환 지정, 목적별 제목 공식·본문 중심 안내 | 브리프의 "발행 채널"([PRD.md#4](PRD.md) P0-02), T01/T05/T06 | ✅ |
| H2 제목 | **메인 키워드 1 + 세부 키워드 1개 이상 필수**([규칙]), F1/F2 공식, 9항목 점검 | `titles.ts`(패턴·경고), Title Lab 평가(P0-03) | ✅ |
| H3 키워드 세트 | 메인 1 + 세부 3+ + 서브 | `keywords.ts`, 키워드 화면 | ✅ |
| H4 썸네일 | 문구 후보, 8항목 점검표(수동 체크) | 편집기 검수 패널(`qa.ts`/`review.ts`) | ✅ |
| H5 본문 품질 | 직접 경험·실제 화면·도입부 점검(규칙 기반 경고, 차단 아님) | QA Center(P0-06) 경고 패턴 | ✅ |
| H6 성과 기록 | 지면별 조회(홈판/검색/기타)·댓글·이웃 증가·썸네일 유형 수동 입력 | `blog-metrics.ts`, 개선 큐(P0-14) | ✅ |

| H9 프롬프트 보관함 | 제목·썸네일·본문 프롬프트 버전 관리 | AI Writer 프롬프트 버전(P0-05) | 후속 |

## 4. 사용자 흐름
1. 키워드 세트 작성(메인·세부·서브) → 2. 글 목적 선택 → 3. Title Lab에서 규칙 통과 제목 선택 → 4. 썸네일 문구·점검 → 5. 본문 작성·검수(직접 경험·화면) → 6. 승인 → 7. **수동 발행** → 8. 공개 URL 확인 → 9. 2주 뒤 지면별 성과 기록 → 10. 개선 큐로 제목·썸네일 유형 비교.

## 9. 수익화·리스크
- 홈판은 **트래픽(구경형 독자)**, 검색·전환글이 **수익**이라는 구분은 [자료] 주장이다. 수익은 전환글에서만 연결한다.
- 위험: 근거 약한 노하우를 사실처럼 표시, 광고성 글 비율 증가로 신뢰 저하, 정책 변경. 대응: 근거 등급 표시, 비율 기록, 규칙 문서 버전 관리.

## 10. 1차 구현 범위 (r2, 2026-11-16 사용자 착수 지시)
사용자가 단계 0 기록 전 착수를 지시했다. 단계 1·2의 MVP(H1~H6)를 **별도 메뉴 화면 + 브라우저 저장**으로 먼저 만든다. DB 저장(마이그레이션·RLS)은 후속.

| 항목 | 내용 |
|---|---|
| 메뉴 | `/naver-homefeed` "네이버 홈판", "키워드 · 제목 랩" 다음 |
| H1 글 목적 | 발견→F2, 문제해결·전환→F1. 목적별 본문 중심 안내(규칙 1장) |
| H2 제목 점검 | 규칙 3.5의 9항목. 자동: 메인 정확히 1회·세부 1개 이상·27자 안·반복 없음·후킹(발견글 필수)·썸네일 문구와 다름·목적-공식 일치. 수동: 읽히는 문장·본문 약속. 과장 표현은 `titleWarnings` 재사용 |
| H3 키워드 세트 | 메인 1 + 세부(3개 미만 경고) + 서브, 중복 경고 |
| H4 썸네일 | 문구 + 유형(사진/스크린샷) + 규칙 4장 8항목 수동 체크 |
| H5 본문 점검 | 도입부 메인 키워드, 직접 경험 문단, 화면·이미지, 세부 키워드 사용, 끝 질문, 금지 표현(노출·수익 보장) |
| H6 성과 기록 | 규칙 8장 항목 수동 입력, 썸네일 유형·공식별 평균 비교, 데이터 없으면 N/A, 목적 비율(목표 5:3:2) |
| 공통 | 모든 점검은 경고(발행 차단 없음), 기존 글 불러오기(제목·본문 읽기만), AI·네이버 API 호출 없음(§11에서 제목 생성에 한해 추가), 3구간·키보드·빈 상태·저장 실패 |

## 11. 레퍼런스 기반 AI 제목 생성 (r3 초안, 2026-11-16 사용자 결정)
결정: 상위 글은 **키워드 기준 상위 10**(네이버 검색 API 블로그 검색), 연관 키워드는 **네이버 검색광고 API 키워드 도구**. 카테고리별 상위 블로그 공식 API는 없고 화면 수집(스크래핑)은 하지 않는다.

| 항목 | 내용 |
|---|---|
| 서버 env | `NAVER_SEARCH_CLIENT_ID`·`NAVER_SEARCH_CLIENT_SECRET`(openapi.naver.com `/v1/search/blog.json`, display=10, sort=sim), `NAVER_AD_API_KEY`·`NAVER_AD_SECRET_KEY`·`NAVER_AD_CUSTOMER_ID`(api.searchad.naver.com `/keywordstool`, HMAC-SHA256 서명). 브라우저에 키를 보내지 않는다. 미설정 소스는 "연결 안 됨"으로 표시하고 나머지로 진행 |
| R1 `POST /api/naver/research` | 입력: 메인 키워드(+세부). 출력: 연관 키워드 상위 20(월간 PC·모바일 검색수, 경쟁도, "< 10"은 그대로 표시), 상위 10 글(제목 태그 제거·엔티티 해제, 링크, 작성일, 블로그명), 상위 제목의 키워드 빈도. 저장 없음 |
| R2 `POST /api/naver/titles` | 입력: 글 목적·키워드 세트·R1 요약. 기존 AI 설정(`resolveDraft`)으로 제목 5개 JSON 생성 → 서버가 §10 제목 9항목 점검과 **상위 제목 베끼기 검사**(동일·고유사 시 경고) 결과를 붙여 반환 |
| 보호 | 기존 `/api/ai/generate`와 같은 순서: sameOrigin → 로그인 → 편집 권한 → 요청 제한(분당 10) → 입력 크기 제한. 상위 글 제목·요약은 프롬프트에 **데이터로만** 넣는다(지시 무시 문구). 외부 응답 시간 제한·크기 제한 |
| 화면 | 네이버 홈판 "제목" 섹션: "레퍼런스 분석" → 연관 키워드(눌러서 세부·서브에 추가), 상위 10 제목(새 탭 링크), 빈도 → "AI 제목 생성" → 후보별 점검 결과, 선택 시 제목에 적용. 모든 텍스트는 React 텍스트로 표시 |
| 비범위 | 결과 DB 저장, 예약 수집, 카테고리 순위, 노출 예측 |

### 11.1 challenger r1 반영 (r3)
| 지적 | 결정 |
|---|---|
| 로컬 모드 무인증 노출 | naver 라우트는 계정 모드(편집 권한), 또는 로컬 모드이면서 Host가 `localhost`·`127.0.0.1`일 때만 허용. 그 외 503 |
| 검색광고 키 피해 범위 | 운영자는 **비즈머니 0인 전용 광고주 계정** 키를 쓴다(README 안내). 코드는 `GET /keywordstool` 고정 경로만 서명. 외부 오류 본문은 응답·로그에 넘기지 않고 상태 코드만 매핑 |
| agent_runs task 제약 | 마이그레이션 없이 `task: "draft"` + `prompt_version: "naver-title-v1"`로 기록(비용 장부에서 prompt_version으로 구분) |
| "상위 10" 표현 | 화면 문구: "검색 API 관련도순 10건(실제 노출 순위 아님)" |
| keywordstool 계약 | hintKeywords 공백 제거·최대 5개, 서명 `{timestamp}.GET./keywordstool`(query 제외), 고정 벡터 HMAC 단위 테스트 |
| 부분 실패 | R1 응답에 소스별 `{status: ok·not_configured·error, message}`. 401→"키 확인", 429→"한도 초과", 시간 초과. 외부 호출 8초·응답 256KB 제한 |
| 프롬프트 인젝션 | 상위 글은 데이터 블록으로만 전달. R2는 R1 요약을 서버가 재검증·절단(제목 10건·각 100자, 키워드 30개·각 30자). AI 출력은 문자열 5개·각 60자 이하·URL 금지로 엄격 파싱, 실패 시 502 |
| 쿼터 | 요청 제한 키 `naver:`(분당 10) 분리, 같은 키워드 R1 결과 10분 메모리 캐시 |
| 링크 | `https:`만 허용, `target="_blank" rel="noopener noreferrer"` |
| 베끼기 기준 | 공백·기호 제거 후 동일, 또는 글자 바이그램 Dice 유사도 0.8 이상이면 경고. 비교 대상은 클라이언트가 보낸 참고 제목(R1 결과를 서버가 재대조하지 않음, 보조 경고용) |
| 키워드 빈도 | 공백·기호로 나누고 흔한 조사(은·는·이·가·을·를·의·에·로·으로·와·과·도) 꼬리 제거, 1글자 제외 |
| 약관 | 네이버 검색 API·검색광고 API 이용 약관(표시·출처·저장·목적)은 **사용자 확인 필요**. 화면에 "출처: 네이버 검색 API·검색광고 API" 표기, 결과 저장 안 함 |
