### 4.1 C1 승인 차단 설계 (r3, 2026-11-16 사용자 결정: 승인 차단 · challenger r1 반영)
| 항목 | 내용 |
|---|---|
| 차단 대상 링크 | 제목·본문에 `coupa.ng` 또는 `link.coupang.com` 호스트(대소문자 무시). C4가 생기면 입력된 BC 링크도 포함 |
| 경고만(C6) | `naver.me`(지도·카페 공유와 구분 불가) → "브랜드커넥트 링크라면 고지 필요" 경고 |
| 고지 판정 | 판정 창 = 제목 + 본문(CRLF→LF, `#`로 시작하는 줄 제거, 줄바꿈 유지) 앞 300 **코드 포인트**. 창 안에 `(수수료\|대가\|원고료)`와 `(제공받\|지급받\|받습니다\|받았)`가 모두 있고, `받을 수 있`이 **없어야** 통과(모호 표현 우선 불합격) |
| 합격 예 | "이 포스팅은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다." · "쿠팡 파트너스 활동으로 수수료를 받습니다." · "이 글은 원고료를 지급받아 작성했습니다." |
| 불합격 예 | "소정의 수수료를 제공받을 수 있습니다." · "파트너스 활동을 하고 있습니다." · 고지가 300자 뒤(글 하단)에만 있음 |
| 적용 시점 | **진입 시에만** 검사: 앱은 별도 함수 `disclosureErrors`를 `approvalRejection`(qa_pending·approval_pending·approved 진입)과 로컬 `applyReviewRule` 진입에서만 호출. `reviewErrors`에는 넣지 않음 → 기존 승인 글의 전달·WP 전송(`delivery.ts`·`wordpress.ts`)·HTML export는 그대로 |
| DB | 새 0028: `article_disclosure_ok(a)` 함수를 만들고 `enforce_article_rules`(0014 트리거 정의 기준)에 "`new.state = 'approved'`이고 `old.state is distinct from 'approved'`이고 old가 gated가 아닐 때"만 검사 추가. `article_review_ok`(0002)는 바꾸지 않음 → 게시된 제휴 글의 monitoring 전이·큐 완료 함수 영향 없음 |
| 일치 시험 | 같은 픽스처(경계 300자, CRLF, `#` 줄, 이모지, 대문자 호스트, 합격·불합격 예문)를 단위 테스트와 `supabase/tests` 양쪽에서 실행. rls 시험에 "기존 published 제휴 글 → monitoring 성공" 추가 |
| 범위 밖 | 공백 삽입("link.coupang .com")·다른 편집기에서 붙여 넣은 링크 우회, 켈빈 기호·전각·퍼센트 인코딩 호스트(작성자 본인 우회, 알려진 한계로 픽스처에 기록), 로컬 모드에서 저장소를 직접 고친 경우 |
| r4 정정 (reviewer r1) | 진입 시점은 계정 API·로컬·DB 모두 **approved 진입만** 차단(편집기는 검수 요청 때 미리 경고). 모호·부정 표현 `받을 ?수`·`받지 않`이 창에 있으면 불합격. 판정은 "고지 문구 존재 확인" 수준의 가드레일이며 문장 의미를 판정하지 않음 |

### 4.2 C2·C3 쿠팡 연동 설계 (r1, 2026-11-16 사용자 위임 결정: 키 없이 코드 먼저, 키 넣으면 동작)
| 항목 | 내용 |
|---|---|
| 서버 env | `COUPANG_ACCESS_KEY`·`COUPANG_SECRET_KEY`. 미설정이면 "연결 안 됨", 버튼 비활성 |
| 인증 | 고정 호스트 `https://api-gateway.coupang.com`, CEA HMAC-SHA256: signed-date `yyMMddTHHmmssZ`(GMT), 메시지 = signed-date + method + path + query, 서명 hex. `Authorization: CEA algorithm=HmacSHA256, access-key=…, signed-date=…, signature=…` [자료, 공식 도움말 미열람] |
| C2 `POST /api/coupang/search` | `{keyword}` → `GET …/products/search?keyword&limit=10&subId`(subId = `contentflow`). 반환: 상품명·가격·로켓 여부·제휴 URL(https만). 이미지는 표시하지 않음 |
| C3 `POST /api/coupang/deeplink` | `{url}`: `https://(www.\|m.)?coupang.com/…`만 허용 → `POST …/deeplink {coupangUrls:[url]}` → 단축 링크(호스트 `link.coupang.com`·`coupa.ng`만 수용) |
| 보호 | naver 라우트와 같은 가드(sameOrigin→로그인→편집 권한, 로컬은 loopback Host만). 요청 제한 `coupang:` 분당 10 + 프로세스 전체 시간당 20(호출 제한 수치 미확인이라 보수적), 검색 30분 메모리 캐시, 8초·256KB, 외부 오류 본문 비노출 |
| 편집기 | "쿠팡 상품" 패널: 검색·URL 변환 → "링크 넣기"가 `[상품명](링크)` 줄을 본문 끝에 추가. 고지가 없으면 기존 C1 안내·"고지 문구 넣기" 표시. 가격 옆 "조회 시점 기준" |
| 비범위 | 자동 글 생성(C5), 리포트(C7), 상품 이미지 재업로드 |
| r2 정정 (challenger r1) | ① **단일 소유자 전용**: env 키는 로컬 모드, 또는 계정 모드에서 `COUPANG_OWNER_WORKSPACE_ID`와 같은 워크스페이스에서만 동작(다른 워크스페이스는 "이 워크스페이스에서는 사용할 수 없음"). 워크스페이스별 키 저장은 후속 ② 활성화 스위치 `COUPANG_ENABLED=1`이 있어야 호출(호출 제한 공식 확인 후 켬) ③ 전역 한도는 `sharedLimited(…,"coupang:global")`로 시간당 10, 사용자 분당 5. 같은 키를 여러 환경에서 쓰지 않음 ④ subId는 고정 채널 ID `COUPANG_SUB_ID`(기본 `contentflow`, 영숫자만), 글 ID는 C7에서 재판단 ⑤ C2 결과도 `link.coupang.com`·`coupa.ng` 호스트만 수용, 아니면 버림 ⑥ 서명은 고정 입력 테스트 벡터로 고정, **첫 키 투입 후 실호출 1회 확인**이 완료 조건. 401/403은 "키·서명 확인" 문구만 |

### 4.3 C4·C6 설계 (r1, 2026-11-16 팀장 결정)
| 항목 | 내용 |
|---|---|
| C4 브랜드커넥트 링크 | 편집기 "브랜드커넥트 링크" 패널: 사용자가 BC에서 발급한 링크(https, 호스트 `naver.me`·`brandconnect.naver.com`·`shoppingconnect` 포함 네이버 호스트만) + 상품명 + 수익분배율(선택, 표시용 메모) 입력 → "링크 넣기"가 `[상품명](링크)` 줄을 본문 끝에 추가하고, 고지가 없으면 본문 맨 앞에 BC 고지 문구(§4)를 함께 넣는다. 외부 호출·"연결됨" 표시 없음 |
| C4 차단 범위 | BC 링크는 `naver.me`와 구분할 글 단위 표시가 없어 **승인 차단 대상이 아님**(C1은 쿠팡 호스트만). 글 단위 제휴 표시(DB 필드)는 후속 마이그레이션에서 결정 |
| C6 저품질 경고 (`qa.ts`, 차단 아님) | ① 제휴 링크(쿠팡 호스트+naver.me) 4개 이상 ② 본문 앞 300자 안에 제휴 링크(도입부부터 상품 링크) ③ 다른 제휴 글과 소제목(`#` 줄) 구성이 완전히 같음(같은 형식 반복) |
| 비범위 | 홈판 글 목적(발견글) 연동 — 글 목적은 네이버 홈판 화면의 브라우저 저장이라 글과 연결 안 됨 |

### 4.4 글 단위 제휴 표시 (r1 초안, 2026-11-17)
| 항목 | 내용 |
|---|---|
| 목적 | BC 링크(naver.me)처럼 호스트로 구분할 수 없는 제휴 글도 C1 승인 차단 대상으로 만든다 |
| 데이터 | `articles.affiliate` boolean not null default false(마이그레이션 0029). 로컬 모드는 글 JSON `affiliate` 필드(없으면 false) |
| 설정 | 편집기 체크박스 "제휴·광고 글(대가 고지 필요)". C4 "링크 넣기"·C2/C3 "링크 넣기" 시 자동으로 켬. 끄는 것은 편집 권한자만, 끄면 승인 해제(내용 변경과 동일 취급) |
| 차단 | approved 진입 시 `affiliate = true` 또는 쿠팡 호스트 → 고지 필수(앱·DB 동일). 기존 글은 false라 영향 없음 |
| 해시 | 승인 해시(`article_content_hash_v2`)는 바꾸지 않음. 대신 `affiliate` 변경을 트리거의 `changed` 판정에 포함해 승인 해제 |
| 비범위 | 자동 판별(AI), 과거 글 일괄 표시 |
| 스냅샷 의미 | `article_versions.affiliate`는 **승인 시점 값**. 승인 뒤 켠 표시는 export·게시를 막지 않고 스냅샷에도 반영되지 않음(다음 재승인부터 적용). 해제(true→false)는 `audit_logs` `article.affiliate_removed`로 기록 |
| r2 정정 (challenger r1, 팀장 결정) | ① `affiliate`는 트리거 `changed`·앱 `contentChanged`에 **넣지 않음**(게시 글 URL·승인 유지). ② false→true는 편집 권한자와 reviewer 모두 허용(어느 상태든), **true→false는 owner·admin만**(DB 트리거가 역할 확인, 로컬 모드는 단일 사용자라 허용). ③ reviewer 금지 목록에 true→false 명시. ④ `article_versions`에 `affiliate` 스냅샷 컬럼 추가(승인 기록 감사). ⑤ 저장 요청에 `affiliate`가 없으면 기존 값 유지(`!== undefined`일 때만 씀), 로컬 JSON은 `undefined\|boolean`만 허용. ⑥ 배포 순서: 0029 적용 → 앱 배포. ⑦ 판정 함수(JS `disclosureErrors`·SQL `article_disclosure_ok`)가 affiliate를 입력으로 받고, 픽스처에 affiliate 케이스 추가. RLS 시험: editor·reviewer의 해제 거부, admin 해제 허용, 게시 글에서 켜도 URL·승인 유지 |
