## A. 네이버 검색 API (블로그 검색) — NAVER API 서비스 이용약관 (2026-10-07 개정)
URL: https://developers.naver.com/products/terms/  (curl로 원문 수신, WebFetch는 차단됨)

1. 출처 표기 [원문확인] 특약 2.1 "검색 API 서비스는 애플리케이션 등에서 네이버 검색결과를 제공하기 위한 목적으로만 이용될 수 있습니다. 이용자는 네이버의 BI 가이드에 따라 … 네이버 검색결과임을 표시하여야 합니다."
   특약 2.2 "…데이터 원본의 출처를 표시하고 원본으로 이동할 수 있는 링크를 제공하여야 합니다."
2. 가공 금지 [원문확인] 특약 2.2 "제공받은 데이터를 독립적으로, 가공 없이 노출하여야 합니다. 검색결과의 앞, 뒤, 중간 등에 다른 내용을 삽입하거나, 순위 및 내용을 수정, 변조 또는 왜곡할 수 없고…"
3. AI 입력 금지 [원문확인] 특약 2.3 금지행위: "데이터를 AI에 입력하거나 학습, 개선, 평가 및 노출 등에 활용하는 행위" (데이터 = "그 가공 또는 파생물도 포함")
   → 블로그 제목을 AI 프롬프트에 넣어 제목 후보를 만드는 것은 문언상 정면으로 금지.
4. 저장·캐시 [원문확인] 특약 2.3 "데이터…를 복사, 저장 또는 캐싱하는 행위 (단, 2.4.에 해당하는 경우 제외)"
   특약 2.4 "서비스 연속성을 유지하기 위해 필요한 범위에 한하여 … 임시 보관(캐싱)할 수 있습니다." 기기: 24시간 또는 새 질의 시까지 중 짧은 기간. 서버: "이력 조회 목적으로 최대 21일. 개인화 서비스 제공 목적으로는 … 24시간 또는 새 질의 시까지 중 더 짧은 기간 (목적별 분리 보관)"
   → 10분 메모리 캐시는 기간상 범위 안. 다만 "서비스 연속성" 목적이어야 하고, 워크스페이스 간 공유 캐시는 목적 설명이 필요(조건부).
   일반조건 7.3③ "취득한 정보…를 … 무단으로 복제, 저장(캐시 행위 포함), 가공, 배포 등 이용하거나 제3자에게 제공하는 행위" 금지.
5. 상업적 이용 [원문확인] 특약 2.3 "검색결과가 표시되는 페이지에 광고를 표시하거나, 기타 검색 API 서비스를 활용하여 수익을 얻는 행위" 금지.
   일반 7.2③ "그 사용자들로부터 API서비스 이용에 대한 대가(금전, 정보 제공 등 일체의 유·무형의 대가)를 제공받아서는 안됩니다."
   일반 7.3④ "API의 결과화면과 함께 광고를 노출하는 행위" 금지.
   → 유료 SaaS 요금제 안의 기능으로 제공하면 "수익을 얻는 행위"로 해석될 위험이 높음.
6. 키 공유·다수 고객 [원문확인] 일반 7.2② "클라이언트 아이디를 타인에게 제공, 공개하거나 공유할 수 없습니다."
   7.3⑤ 허용량 증가 목적으로 "다수의 클라이언트 아이디를 사용하여 API를 호출" 금지. 7.3⑥ "어플리케이션 등을 통해 API서비스를 다시 제3자에게 제공하는 행위" 금지. 6.2 "하나의 어플리케이션 등에는 하나의 클라이언트 아이디만"
   → 서버에서 우리 키 1개로 호출하고 키를 노출하지 않으면 7.2②는 충족. 그러나 여러 고객 워크스페이스에 검색 기능을 파는 구조는 7.3⑥(재제공) 해석 위험(조건부·불명확).
   → 워크스페이스별로 고객 자신의 키를 받는 방식(BYOK)은 7.3⑥ 위험을 줄이지만, 2.3 AI 입력 금지는 그대로 남음.
7. 호출 한도 [원문확인] https://developers.naver.com/docs/serviceapi/search/blog/blog.md "검색 API의 하루 호출 한도는 25,000회입니다." / https://developers.naver.com/docs/common/openapiguide/apilist.md "API 사용량은 클라이언트 아이디별로 합산됩니다."(블로그 문서 내 동일 문장)
8. 신규 신청 중단·이관 [원문확인] 약관 부칙 제2조 ①: 2026-07-30 24:00 기점 개발자센터 'Search API' 신규 이용 신청 중단. ② 그 전 신청자는 2027-06-30까지 제공. ④ 2027-07-01부터 개발자센터 제공 종료, NAVER API HUB 약관 적용.
   → 현재(2026-11) 키가 없다면 개발자센터에서 새로 받을 수 없음. 우리 키 보유 여부 확인 필요.

- [원문확인] https://github.com/naver/searchad-apidoc README: 키는 검색광고 광고주센터(manage.searchad.naver.com) 도구 > API 관리에서 발급 = 광고주 계정 단위 라이선스.
- [원문확인] https://naver.github.io/searchad-apidoc 공지 2020-12-18 "키워드 도구 기능의 빈번한 429 에러": 사용량 제한은 "호출 대상 계정당 속도 제한", 키워드 도구는 "다른 오퍼레이션 대비 호출 속도는 1/5~1/6 수준", 속도 단위에 "호출 클라이언트의 IP 정보도 포함". 429 시 5~6배 긴 대기, 대량 429 시 "최소 5분 이상 모든 호출을 중단". 고정 일일 한도 수치는 공개 문서에 없음.
- [원문확인] keywordstool 스펙(ncc-keywordstool.json): hintKeywords 최대 5개, 연관 키워드와 검색수·경쟁도 반환. 스펙에 사용 목적 제한 문구 없음.
- [미확인] 검색광고 API 이용약관/광고 이용약관 원문: ads.naver.com/terms는 JS 렌더링 페이지라 본문 수신 실패, searchad.naver.com 약관 URL은 404. 광고 관리 외 목적(콘텐츠 키워드 조사)·제3자(다수 고객) 제공·저장 제한 조항은 확인 못 함 → 사람이 로그인 후 광고주센터 API 약관 동의 화면 원문을 확인해야 함.
- [미확인] 하나의 광고주 계정 키로 여러 SaaS 고객에게 키워드 데이터를 보여주는 것의 허용 여부. 공식 도구(광고주센터 키워드 도구)와 같은 데이터라 저위험으로 흔히 쓰이지만 약관 근거는 없음.

## E. 필요한 제품 변경
1. 블로그 검색 결과(제목·블로그명 등)를 AI 입력에서 제거. AI 제목 생성은 운영자 입력 키워드 + (확인 후) 키워드 도구 연관어만 사용.
2. 블로그 결과 패널: "네이버 검색결과" BI 표기, 각 항목 원본 링크, API 순서 그대로, 우리 점수·요약·광고를 같은 목록에 섞지 않음.
3. 캐시는 메모리 10분 유지, DB·로그에 결과 본문 저장 금지(현재 설계 유지).
4. 상용(유료 플랜) 출시 전: 블로그 검색 기능을 끄거나 네이버 제휴/법무 확인. BYOK(워크스페이스 자체 키) 검토.
5. Search API 키 보유 여부 확인. 없으면 2026-07-30 이후 신규 발급 불가 → API HUB(유료·별도 약관) 경로만 남음.
6. 키워드 도구: 광고주센터 API 약관 원문을 사람이 확인해 이 문서 C절 [미확인] 해소. 429 시 5분 중단 백오프 구현.
