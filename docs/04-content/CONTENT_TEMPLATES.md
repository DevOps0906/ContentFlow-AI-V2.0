# Content Templates & Title Lab — v2.1

MVP는 T01/T02/T04이며 나머지는 후속 카탈로그다. 이 문서의 글쓰기 템플릿은 설치형 블로그 스킨과 다르다. [수익화 기획](../01-planning/MONETIZATION_STRATEGY.md)의 표시/광고 프로필과 조합한다.

## 1. 편집 기준
검색 의도/독자/플랫폼에 따라 구성 블록을 선택한다. 길이, 사진 수, 키워드 밀도를 검색 순위 공식처럼 사용하지 않는다. 출처 없는 정책·세금·건강 정보는 발행 보류. 실제로 사용하지 않은 상품의 허위 후기를 작성하지 않는다.

## 2. 플랫폼 변환 프로필
| 플랫폼/유형 | 제목 | 구조 | 발행 |
|---|---|---|---|
| 네이버 검색형 | 핵심 키워드+대상/해결 | 답변 선제시, 실제 경험, 시각자료 | 수동 |
| 네이버 홈판형 | 관심·맥락+구체성 | 스토리, 검증된 경험/사진 | 수동 |
| 티스토리 | 문제+해결 방법+조건 | 롱테일, H2/H3, 단계, FAQ | 수동 |
| WordPress | 검색 의도+독자적 근거 | 내부링크·출처·기술 SEO | REST API |
| Blogger | 검색 의도+차별화 | 구조화된 정보·출처·내부링크 | Blogger API |

## 3. 10개 글쓰기 템플릿
| ID | 유형 | 필수 블록 |
|---|---|---|
| T01 | 검색형 정보 가이드 | 바로 답변 → 대상/조건 → 단계 → 주의 → FAQ/출처 |
| T02 | 오류 해결형 | 증상/오류문 → 원인 → 우선 점검 → 해결법 → 성공 확인 |
| T03 | 정부지원/환급형 | 기준일 → 대상 → 기간/조건 → 공식 신청 절차 → 주의 |
| T04 | 가격/서비스 비교형 | 비교 기준 → 가격/기능 표 → 장단점 → 대상별 추천 |
| T05 | 실사용 후기형 | 사용 환경/증거 → 직접 사용 과정 → 장단점 → 한계 |
| T06 | 네이버 홈판 스토리형 | 맥락 → 검증된 상황/경험 → 변화 → 독자 의미 |
| T07 | 쇼핑 제휴 비교형 | 경제적 관계 고지 → 구매 기준 → 비교 → 제한 → 링크 |
| T08 | 이슈/시즌형 | 사실 기준 시각 → 변화 → 영향 대상 → 공식 발표/후속 |
| T09 | 전문 튜토리얼형 | 환경/버전 → 예상 결과 → 설치 → 실행 → 검증/FAQ |
| T10 | GEO/전문 리서치형 | 핵심 결론 → 방법 → 원본 데이터 → 분석 → 한계/출처 |

## 4. 제목 공식
- 문제해결: `[오류] 해결 방법: [원인]과 [조치]`
- 비용: `[서비스] 비용·추가 비용 총정리`
- 비교: `[A] vs [B]: 가격·기능·선택 기준`
- 대상: `[대상]을 위한 [절차] 신청 방법`
- 실수방지: `[작업] 전 확인할 실수 N가지`
- 경험: `[상품] 실제 사용 환경과 장단점` (실제 사용 증거 필요)
- 업데이트: `[제도] 변경사항: 대상·일정` (기준일 필수)
- 추천피드: `[상황]에서 중요했던 [변화]` (본문과 일치)

**내부 100점 평가:** 의도30, 명확20, 구체20, 차별15, 자연스러움10, 과장금지5. 검색 상위노출을 예측하는 점수는 아니다.

## 5. 공통 Markdown 본문 골격
```markdown
# [검색 의도와 일치하는 제목]
[핵심 질문에 대한 직접 답변 — 실제 확인 근거 중심]

## 1. 개념·대상 또는 상황
[누구에게 어떤 문제인가]

## 2. 해결·비교·실행 과정
### 1단계
[절차와 확인 가능한 증거]
### 2단계
[절차와 예외]

## 3. 비용·조건·주의 사항
[근거·기준일이 있는 정보]

## 4. FAQ
### Q. [실제 질문]
[짧고 정확한 답]

## 5. 마무리
[핵심 요약, 다음 행동, 관련 내부 링크]

### 출처
- [공식 문서 URL] (확인: YYYY-MM-DD)
```

## 6. AI Writer 입력 계약
```json
{
 "platform":"wordpress",
 "template_id":"T02",
 "primary_keyword":"Next.js 포트 오류",
 "search_intent":"troubleshooting",
 "audience":"Windows 개발자",
 "verified_sources":[],
 "original_evidence":[],
 "reference_date":"2026-11-05",
 "internal_links":[],
 "affiliate_disclosure":false
}
```

출력: `title_candidates[5]`, `selected_title`, `outline`, `markdown`, `claims`, `sources`, `image_slots`, `qa_flags`, `metadata`. 실제 프롬프트/JSON schema는 코드에서 별도 버전 관리한다.

## 7. SEO/GEO 검수
- H1 1개, 자연스러운 H2/H3, 키워드 반복/어뷰징 금지.
- 중요한 주장마다 출처; 확인 안 된 가격·정책은 단정하지 않음.
- 고유 경험·수치·예시 또는 독자적인 분석 추가.
- 권한 있는 이미지 사용, 적절한 대체텍스트, 모바일 가독성.
- 관련 내부 링크는 실존하는 URL로만.
- 광고 링크와 본문 사이 경계 명확히 구분.

## 8. 첫 3개 검증 콘텐츠
1. Next.js 포트 개념·점검 가이드(T01 정보)
2. 실제 재현한 Next.js 포트 오류(T02 오류 해결)
3. n8n vs Make(T04 비교)
원고 생성시간/수정시간/출처 검증 실패율/검색 색인을 기록하여 템플릿의 가치를 검증한다.

## 9. v2.1 버전·필수 입력·차단 계약

| MVP | 추가 입력 | 필수 증거/완료 조건 |
|---|---|---|
| T01 정보 | 독자 질문, 적용 조건, 확인일 | 직접 답변, 출처와 한계, 실존 관련 URL |
| T02 오류 | 환경/버전, 재현 조건, 오류문 | 실행 절차, 결과 확인, 실패 시 대안; 미실험은 미실험으로 표시 |
| T04 비교 | 비교 대상/버전, 동일 기준, 가격 기준일 | 항목별 출처/조건, 대상별 선택 근거; 제휴 시 고지 |

기존 6절 JSON은 필드 구조 예시다. `verified_sources: []` 상태로 사실 주장 원고를 승인할 수 없다. 브리프 단계에서 자료가 없으면 조사 대기이며 `original_evidence`가 없을 때 경험/실험을 만들어내지 않는다. 첫 파일럿 예제는 T01의 Next.js 포트 개념·점검 가이드, T02의 실제 재현한 포트 오류 해결, T04의 n8n/Make 비교로 구성한다. 정부 절차 예제는 T03 후속으로 이동한다. T01/T02가 같은 의도를 겨냥하면 두 글을 별도 발행하지 않고 합친다.

추가 입력 필드: `content_template_version`, `layout_profile_version`, `ad_profile_version`, `renderer_version`, `blog_id`. 선택 시 네 버전의 존재/플랫폼 호환성을 검사한다. 모델은 의미 블록을 출력하고 renderer가 표시와 placeholder를 처리한다.

## 10. 표시/광고 프로필과 인수 시나리오

- L01 읽기 중심: 제목·직접 답변·목차·본문·출처·작성자/수정일·관련 글.
- L02 비교 중심: L01 공통 요소 + 모바일 비교표/기준/장단점/선택 안내.
- A00: 광고 없음 기본. A01: 의미 블록 사이 후보 위치만 미리보기. 코드/표/절차/버튼 내부 제외, 실제 광고 script는 패키지에 포함하지 않음.
- 360/768/1440px에서 본문 넘침, 표 스크롤, 이미지 영역, 목차·키보드 이동, 광고와 동작 버튼 구분을 확인한다.
- 렌더러 r2: T01/T02/T04의 템플릿 소제목(`##`, 코드펜스 안 제외)이 하나라도 없으면 `필수 블록 누락: <이름>`으로 QA·승인·전달 차단(계정 모드 승인 API 포함). 소제목 2개 이상이면 첫 소제목 앞에 목차(앵커 `cf-s{n}`), 둘째 줄이 `|---|` 구분선인 `|` 줄 묶음은 표(GFM, 모바일 가로 스크롤, `\|`는 문자), 구분선이 없으면 문단. r1로 승인된 글은 재승인.
- 필수 블록/출처 누락 시 QA 차단; 표시/광고 프로필 변경 시 새 렌더와 재승인; 본문 script/event handler 차단; 이전 버전 패키지 재생성 가능.
- 미리보기 이미지는 설치 가능한 스킨의 증거가 아니다. 후속 스킨은 플랫폼별 설치/지원 버전/라이선스/복구 절차까지 있어야 완료다.
